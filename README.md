# Seasonal warming through time

Static HTML/CSS/vanilla JavaScript with D3 7.9.0 SVG rendering. Serve with VS Code Live Server or `python3 -m http.server 8000`.

Exactly two analytical views are active: a regional trend-difference map and a persistent seasonal anomaly chart. Select seasons, click a 5° region, and move the end-year slider through inclusive 30-year windows (1979 = 1950–1979; 2014 = 1985–2014). Full-period mode starts at 1950–2014 and preserves the last moving-window endpoint. Dragging the slider activates moving mode. Without a selected region, the temporal chart explicitly shows global area-weighted context.

Map fills, map tooltips and chart fits use one OLS implementation on the same regional histories. Slopes are °C/decade. The map domain spans all 36 moving windows plus the full period for the chosen pair, so it never rescales as the slider moves. Anomaly histories remain visible for all 65 years; shading and thick fitted segments show the analysis window. The difference in slopes is distinct from the vertical separation of anomalies. Season names use Northern Hemisphere month conventions everywhere.

## Modules

- `src/main.js`: shared state and two-view coordination; requestAnimationFrame slider scheduling.
- `src/trends.js`: pure period/OLS helpers, cached regional rate arrays, pair-wide color domains.
- `src/map.js`: D3 geographic paths, regional fills, selection, tooltip and legend.
- `src/temporal-chart.js`: D3 histories, shaded period and fitted trend segments.
- `src/data.js`: cached relative asset loading, including compatibility loaders.
- `src/state.js`, `src/geo.js`, `src/seasons.js`, `src/tooltip.js`: shared utilities.

Legacy ranking, histogram, selectors and detail modules remain on disk for compatibility/tests but are not imported by the active application. Geographic brushing/filtering is removed from this workflow; the legacy snapping helper now rejects sub-cell brushes safely.

## Export

Run `uv run python scripts/export_climate_json.py` for base assets and geography, then `uv run python scripts/export_exploration_data.py` for regional bands and the new regional/global anomaly bundles. The latter reads the original NetCDF, uses cosine-latitude weights and finite-value masks, and exports all four seasons and 65 years in stable region order. Regional anomalies are rounded to three decimals; global anomalies to five. Global means are calculated over native cells, not unweighted regional means. The current source has complete finite coverage for every season/year.

The map loads `data/regional_anomalies.json` once rather than fetching native annual grids or band files on slider changes. The chart uses this same bundle plus `data/global_anomalies.json` for its startup context.

## Validation and measured limits

Run `node --test tests/*.test.mjs` and `uv run python -m unittest discover -s tests -p 'test_*.py'`.

Measured maximum full-period discrepancy from legacy regional rates: **0.000074668 °C/decade**, below the explicit 0.0002 tolerance, consistent with anomaly rounding. Every regional seasonal slope is finite for all supported windows. All 260 global anomalies were independently checked against native-cell weighting within 0.0000051 °C.

A local Node measurement took ~238 ms to build the initial Winter/Summer pair domain and slope cache; retrieving all 36 cached seasonal pairs took ~0.04 ms. These measure numerical work, not browser rendering, network transfer or mobile performance.

Browser checks remain manual: desktop/mobile labels, mouse/touch/keyboard slider, rapid slider movement, selection persistence, global context reset, stable legend endpoints and fitted segments. No live deployment or browser performance claim is made.

## Geographic context, brushing and zoom

`data/region_geography.json` is generated by `scripts/export_region_geography.py` from the actual local `110m_cultural/ne_110m_admin_0_countries.shp`, optional `ne_110m_admin_1_states_provinces.shp`, and `110m_physical/ne_110m_land.shp`. These are WGS84 layers: 177 countries, 51 US-only subdivision features, and 127 land features. One invalid land geometry is repaired. The export records geometry diagnostics and warns about optional coverage or overlapping administrative geometries. CLI arguments `--countries`, `--admin1`, `--land`, and `--output` allow other local sources. No runtime geographic network service is used.

The exporter uses spatial-index candidate queries, intersects polygons in WGS84, and measures intersections and blocks using EPSG:6933 (a WGS84 cylindrical equal-area projection). Country/subdivision percentages describe the entire block, not just its land. Land coverage follows the supplied generalized physical land polygons, including their inland-water conventions. Natural Earth 1:110m omits small features; percentages are approximate. Unknown/placeholder ISO codes become null. Latitude bands are neutral geometric descriptors, not climate zones. Dominant-country (70%), substantial-country (10%), and mostly-ocean (10%) thresholds are centralized UI heuristics in `src/geography-context.js`.

Metadata loads once through `loadRegionGeography()`. Failure falls back to coordinate-only labels without breaking climate views. Selected-block details include overlapping countries/subdivisions, latitude band, land fraction, all four current-period seasonal rates, and global signed rank/percentile. Map tooltips use the same geographic formatter.

The Navigate mode supports wheel/touch zoom, drag pan, block selection and hover; +/−/Reset zoom provide button alternatives. Zoom is bounded to 1×–12× and preserves selection. Brush area mode separates rectangle dragging from navigation. Its live tooltip reports the count and coordinates of complete 5° blocks. Screen coordinates are inverted through the current zoom transform and projection before inward snapping. Sub-cell rectangles do not change selection. After release, outlined blocks drive an area-weighted seasonal anomaly history in the existing temporal chart. Weights use each block's spherical area (longitude width × difference of latitude sines), consistent with the native cosine-latitude convention for this regular grid. No country-wide climate statistic is implied. Area selection persists across period/season changes; Return to global context clears it. A single rectangle cannot cross the antimeridian seam.

Legacy statements above about removing geographic brushing apply to the previous migration; this enhancement restores it specifically for area-history selection. No third analytical view is added. Browser verification of zoom, brushing after zoom, touch interactions, and geographic context should be done through Live Server; no browser is launched outside the sandbox.

### Always-on brush interaction

The interaction-mode dropdown has been removed. Dragging always brushes; clicking selects one block, and hovering still shows geographic/climate tooltips over the brush overlay. Scroll zoom and Shift-drag pan are available without toggles. The + button increases scale around the center of the current brushed geographic selection (subject to world-edge constraints); − zooms out and Reset zoom returns to the globe. Selection remains independent of zoom and survives period/season changes. This supersedes the Navigate/Brush mode instructions above.

## Editing presentation

`index.html` owns page structure, controls, static copy, SVG containers and their view boxes. `style.css` owns layout, typography, map base colors, selection borders, history/trend line styling, legend text, tooltips and responsive rules. The active D3 renderers use named CSS classes instead of inline presentation attributes. CSS variables near the end of the stylesheet provide the map defaults, analysis-window color, history opacity and trend width; the appearance controls override map variables at runtime.

JavaScript retains data-driven SVG geometry, axis generation, climate color mapping, dynamic scientific labels and pointer-dependent tooltip placement. Changing chart margins/projection or the mathematical color mapping still requires JavaScript; ordinary page layout and visual styling do not. `.prettierrc.json` records two-space indentation, a 90-character target width and single-quoted JavaScript. All frontend source and JavaScript tests have been formatted consistently. Vendored D3 and generated data are intentionally not reformatted.
